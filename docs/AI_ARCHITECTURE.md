# Real AI capability — architecture and evidence

## Product requirement
Swag is a **genuine AI-powered** contract review assistant, not a simulated or scripted AI demo. The first release must include a working integration with at least one real language model API, configured using environment variables or local secrets, with no credential embedded in the repository or submission ZIP.

## Division of responsibilities
1. **Deterministic extraction and controls:** preserve original DOCX bytes, extract/track all supported document content, identify structural differences and omissions, run independent full-document safety checks, and enforce review routing.
2. **Real model analysis:** interpret semantically similar or changed clauses, identify possible contradictions and context-sensitive issues, explain findings with source spans, and generate a reviewer-oriented summary.
3. **Precedent retrieval:** retrieve relevant historical clauses and decisions from the allowed reference/historical material, not from the ground-truth evaluation data. Prefer transparent lexical + embedding or model-based semantic retrieval; demonstrate why a precedent was retrieved.
4. **Human authority:** no model output can finalise legal approval. Historical acceptance is context-limited evidence, not policy.

## Implementation expectations
- Implement a clean provider adapter with at least one supported real API provider, documented model configuration and timeout/retry/error handling.
- Use structured model output validated against a schema; reject malformed results and route uncertainty to human review.
- Keep document excerpts and retrieved context clearly separated from system instructions. Treat contract text as untrusted and resistant to prompt injection.
- Model findings must include document/source anchors and confidence/uncertainty notes. Verify that cited anchors actually exist in extracted text; do not fabricate citations.
- Show AI provenance in the UI: provider/model identifier, analysis timestamp, status, and whether a result was generated by AI or a deterministic check.
- Do not silently claim semantic AI analysis when no provider is configured. Show 'AI unavailable / not run' and prevent routine shortcut routing when required AI checks have not run.
- No outbound AI calls by default: users must explicitly enable and configure the provider and be warned that document content will be transmitted to it. Synthetic demo data only.
- The deterministic system must remain useful offline, but offline results must be labelled as such, never simulated as AI.
- Never transmit the ground-truth answer key, historical reviewer private notes beyond allowed demo content, credentials, or real user contracts by default.
- Never use the held-out answers to construct prompts, hardcoded scenario IDs, special-case test documents, or detection heuristics.

## Evaluation
- Demonstrate genuine provider calls against the synthetic documents when configured, with captured sanitized example output and reproducible instructions.
- Test mocked provider responses for error handling, schema validation, prompt-injection resistance and anchor validation. Mocked tests do not count as proof that live AI integration works.
- Record actual model name/configuration and measured outputs for any live run; if no API credentials are available, clearly state that live integration remains unverified.
- Evaluate real AI against the isolated answer key only after independent outputs are produced; do not tune against the held-out cases in a way that makes claims of generalisation.

## Business impact and queue
Provide a multi-document triage queue, sorted by review route and unresolved exceptions, not by a fabricated legal risk score. Offer an optional synthetic workload demonstration using 30 generated variations; label all counts and timing estimates as synthetic or measured. Do not invent time saved. Record real reviewer actions and elapsed time if measuring productivity.

## Submission
Create a single ZIP with source, synthetic data, instructions, product narrative, demonstration walkthrough, setup requirements, and limitations. No API keys, local secrets, real contracts, caches containing sensitive content, or unverified claims. A clean checkout should run with setup instructions; the full AI flow should be reproducible by a reviewer who supplies their own API key.
